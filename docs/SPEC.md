# 교실 도구함 개발명세서

기준일: 2026-11-07 · 상태: 두 도구를 제공하는 정적 사이트

현재 범위는 **허브·무작위 번호 뽑기·자리 배정**이다. 급식·시간표와 나이스 조회 기능, 과금 가능한 백엔드, Firebase 연결은 제거한다. GitHub 소스 저장소와 기존 공개 Sites 주소는 유지한다. 과거 학교생활·Firebase 설계와 계획은 `superpowers/` 아래의 역사 기록이며 현재 구현 지침이 아니다.

## 1. 목적과 사용자

앞으로 만드는 웹앱을 한곳에서 찾아 실행하는 도구함이다. 방문자는 검색·분류·즐겨찾기로 도구를 찾고 번호를 추첨하거나 자리를 배정한다. 소유자는 개인 앱 링크를 관리하고, 모든 방문자에게 공개할 앱은 목록 소스를 수정하여 배포한다.

로그인이나 서버 관리자 계정을 만들지 않는다. 브라우저에서 추가한 링크는 현재 브라우저에만 저장되며 다른 방문자에게 공개되지 않는다. 학생 이름·명단·연락처·성적을 받지 않는다.

## 2. 실행 환경과 구성

- PC·휴대전화 브라우저에서 사용하는 반응형 HTML·CSS·JavaScript ES 모듈 사이트다.
- 허브와 두 앱 모두 브라우저에서 동작한다. 외부 API·인증·데이터베이스·비밀 설정을 사용하지 않는다.
- Node.js 22 이상과 내장 기능만으로 로컬 서버·테스트·정적 자원 검사를 실행한다. 패키지 설치가 필요 없다.
- `npm start`로 로컬 정적 서버를 실행하고 `http://127.0.0.1:8000`을 연다. `npm test`와 `npm run build`로 검증한다.
- 운영은 기존 Sites 주소의 정적 호스팅이다. `dist/`의 공개 파일만 제공하며 서버 번들을 만들지 않는다.
- 첫 로딩에 인터넷이 필요하며 도구 실행은 기기 안에서 처리한다. 완전한 오프라인 재방문·PWA·계정·다중 기기 자동 동기화는 범위 밖이다.

## 3. 핵심 시나리오

1. 방문자가 허브에서 도구를 검색하고 연다. 검색 결과가 없으면 검색어를 초기화한다.
2. 1~30번 중 3명을 중복 없이 뽑는다. 제외 번호와 회차 간 중복 방지를 설정하며, 후보가 부족하면 기존 결과를 유지하고 안내한다.
3. 자리 배정에서 학생 수·제외 번호·고정석·빈자리를 정하고 나머지 번호를 배정한다. 다시 섞어도 고정석·지정 빈자리를 유지한다.
4. 개인 앱의 제목·주소·설명을 추가·수정·삭제하고 다음 방문에 다시 사용한다.
5. 개인 앱·즐겨찾기를 JSON으로 내보내 다른 브라우저에 가져온다. 오류·취소 시 기존 자료를 유지한다.

## 4. 기능 요구사항

| ID | 목적·입력 | 처리·출력 | 예외·완료 기준 |
|---|---|---|---|
| FR-001 | 앱 검색: 검색어 최대 100자, 분류 | 제목·설명·분류 검색, 결과 수·카드 표시 | 결과 0건 안내, 초기화 가능 |
| FR-002 | 앱 실행·즐겨찾기 | 내장 앱 내부 이동, 외부 HTTPS 새 탭 실행, 즐겨찾기 로컬 저장 | 외부 링크는 noopener/noreferrer, 저장 불가 안내 |
| FR-003 | 개인 앱 관리: 제목 1~40자, 설명 0~160자, HTTPS URL 최대 2048자, 제공 분류 | 검증 후 개인 목록 추가·수정·삭제 | 위험 프로토콜·인증정보 URL 거부, 삭제 확인, 공개 앱 개인 편집·삭제 불가 |
| FR-004 | JSON 내보내기·가져오기 | 버전 포함 개인 앱·즐겨찾기 백업, 미리보기·확인 후 개인 설정 교체 | 최대 512KB·100앱, 전체 검증 후 적용, 오류·취소 시 원본 보존 |
| FR-005 | 번호 추첨: 시작·끝 1~999, 제외 번호, 추첨 수 1~100, 중복 방지 | 후보를 균등 무작위 섞기 후 선택, 설정에 따라 이전 결과 제외 | 정수·범위·문법·후보 수 검증, 실패 시 이전 결과 보존 |
| FR-006 | 결과·기록·초기화 | 큰 결과, 최근 추첨 기록 최대 20회, 남은 후보, 전체 화면 | 조건 변경 시 새 회차 안내, 초기화는 현재 추첨 세션만 삭제 |
| FR-007 | 자리 배정: 최대 30명, 제외 번호, 고정석·빈자리 | 짝꿍 두 자리씩 3분단·5행의 30석에 나머지 번호 중복 없이 배정 | 고정번호 중복·제외 충돌·범위·좌석 부족 검증, 실패 시 이전 결과 보존 |
| FR-008 | 다시 섞기·인쇄 | 고정석·지정 빈자리를 유지하고 재배정, 배정표 인쇄/PDF 저장 | 조건 변경 후 재배정 전 인쇄 차단, 결과는 현재 탭에만 유지 |

모든 기능은 로그인 없이 사용한다. 중복 방지를 꺼도 한 번의 추첨 안에서는 중복되지 않는다. 번호 범위·제외 번호·중복 옵션을 바꾸면 다음 추첨부터 새 세션을 시작하고, 추첨 수만 바꾸면 기존 회차를 이어간다.

## 5. 화면과 디자인

- 허브: 작은 상단 내비게이션, 다색 텍스트 로고, 중앙 검색창, 두 도구의 빠른 실행, 분류·즐겨찾기 필터, 앱 카드, 개인 앱 추가·관리, 로컬 저장 안내.
- 대화상자: 명시적 레이블·필드 오류·저장·취소·삭제 확인. 열 때 초점 이동, Tab 제한, Escape 닫기, 닫은 뒤 호출 요소로 초점 복귀.
- 번호 뽑기: 데스크톱 좌측 조건·우측 큰 결과, 모바일 한 열. 결과 전·추첨 중·완료·오류 상태 구분.
- 자리 배정: 좌측 설정·우측 칠판과 짝꿍 자리표. 두 책상은 붙이고 분단 사이 통로를 둔다. 편집·결과를 구분하고 상태를 텍스트로 표시한다. 모바일은 자리표 영역 안에서만 가로 스크롤하고 인쇄는 전체 배치를 용지 너비에 맞춘다.
- 이용 안내: 개인 저장 범위·백업·공개 목록 추가 방법·두 도구 사용법을 설명한다.

Google 홈페이지를 참고한 흰 여백·둥근 검색창·다색 포인트를 사용하되 Google 명칭·로고를 복제하지 않는다. 시스템 글꼴·일관된 SVG 아이콘·44px 이상 버튼·뚜렷한 초점·충분한 대비를 사용한다. 색만으로 상태를 구분하지 않고 결과를 live region으로 알리며 모션 감소 설정을 따른다. 구체적인 기준은 [DESIGN.md](../DESIGN.md)에 둔다.

## 6. 데이터와 저장

| 정보 | 저장 위치 | 보관·삭제 |
|---|---|---|
| 공개 앱 메타데이터 | 소스의 `catalog` 배열 | 소유자가 소스 수정·재배포 |
| 개인 앱·즐겨찾기 | 현재 도메인의 localStorage | 개인 삭제·브라우저 데이터 삭제, JSON 백업 가능 |
| 추첨 조건·결과·기록 | 현재 탭 메모리 | 새로고침·초기화 시 삭제 |
| 자리 조건·배정 결과 | 현재 탭 메모리 | 새로고침 시 삭제 |

버전 1 JSON의 `apps`와 `favorites`에 개인 앱과 즐겨찾기를 저장한다. 개인 앱 id는 임의 UUID이고 공개 앱은 고정 id를 사용한다. 가져오기는 필드 허용 목록·길이·id 중복·공개 앱 id 충돌·URL을 검사한다. 개인 앱 삭제 시 관련 즐겨찾기도 삭제한다. 저장 실패 시 현재 탭에서 계속 사용할 수 있고 경고한다. 제거된 급식·시간표 기본 도구의 즐겨찾기는 이전 저장 자료와 백업에서 자동으로 제외하되, 같은 id를 가진 개인 앱과 그 즐겨찾기는 유지한다. 다른 잘못된 즐겨찾기는 계속 거부한다.

## 7. 개인정보·보안

외부 추적·폰트·분석 스크립트를 사용하지 않는다. 사용자 텍스트는 `textContent`로 표시하고 개인 URL은 HTTPS로 제한한다. 링크를 열면 대상 서비스의 정책이 적용된다. 숫자가 실제 학생과 연결될 수 있으므로 추첨·자리 결과는 외부 전송·영구 저장하지 않는다. 무작위 선택은 Web Crypto와 편향 없는 정수 선택을 사용한다.

개인 앱 메타데이터는 브라우저에만 저장되며 백업 파일은 사용자가 관리한다. 중요한 개인 목록은 브라우저 자료 삭제 전에 내보낸다. 호스팅 제공자의 접속 로그는 앱의 별도 데이터 수집과 구분한다.

## 8. 검증과 인수 조건

| 대상 | 검증할 동작 |
|---|---|
| 추첨 | 경계 번호·제외·연속 추첨·후보 소진·초기화, 실패 시 기존 결과 보존 |
| 개인 목록·백업 | 위험 URL·손상 JSON·중복 id·예약 id 거부, 앱 추가→수정→백업→삭제→복원, 제거된 앱 관련 과거 자료 호환성 |
| 자리 배정 | 고정석 유지·지정 빈자리 유지·고유 번호·제외 충돌·중복 고정·좌석 부족·입력 불변 |
| 허브 | 검색·빈 결과·즐겨찾기·재방문, 두 공개 도구 실행 |
| 정적 제공 | 허브·두 앱·JS/CSS 경로 제공, 비공개 경로와 제거된 API/앱은 제공하지 않음 |
| 화면 | 360px~1440px 주요 동작, Tab·Escape·초점, 자리표 내부 스크롤·인쇄 |

실행한 검사와 직접 확인하지 못한 환경은 [검증 기록](VERIFICATION.md)에 구분하여 남긴다. 과거 통과 기록은 현재 코드의 재검증을 대신하지 않는다.

## 9. 배포와 유지보수

소스는 기존 GitHub `webapphub` 저장소에 보관한다. 테스트와 정적 자원 검사를 마친 뒤 기존 Sites 주소에 정적 파일을 갱신한다. 공개 URL·프로젝트를 새로 만들 필요는 없다. 배포·외부 등록 변경·클라우드 리소스 삭제 등 운영 작업의 실제 결과는 별도 운영 기록에 남긴다.

새 도구는 독립 앱 폴더와 공개 목록 항목으로 확장한다. 학생 개인정보·외부 API·서버·계정·동기화가 필요한 기능은 현재 범위에 포함하지 않으며, 요구가 생기면 별도로 설계한다.

## 10. 현재 제외 범위와 제약

- 급식·시간표·나이스 연결, Firebase Hosting/Functions/Secret Manager 구성, Worker 백엔드
- 서버 DB·계정·다중 기기 자동 동기화·실시간 공동 편집·외부 AI·광고·분석
- 완전한 오프라인 재방문과 PWA
- 감사 가능한 공식 추첨 시스템 보장

번호 뽑기·자리 배정·개인 목록·백업 기능은 유지한다. 과거 학교생활·Firebase 문서의 배포나 비밀 등록 명령은 다시 실행하지 않는다.
