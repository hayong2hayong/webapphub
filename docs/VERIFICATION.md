# 검증 기록

현재 제품 범위는 허브·번호 뽑기·자리 배정의 정적 사이트다. 아래 기록은 각 구현 시점에 수행한 검증 이력이며, 급식·시간표·Worker·Firebase 관련 결과는 제거된 기능의 역사 기록이다. 현재 코드의 테스트·빌드·공개 배포 결과는 정적 전환 작업의 실제 실행 결과로 별도 확인한다.

## 정적 사이트 전환 검증 · 2026-11-07

- `node --test`: 남은 핵심·허브 저장·자리 배정 테스트 25개 통과.
- 과거 급식·시간표 즐겨찾기가 전체 개인 목록의 복원을 막는 실패를 먼저 재현했다. 수정 뒤에는 해당 기본 즐겨찾기만 제외하고 개인 앱·다른 즐겨찾기를 보존한다. 같은 id의 개인 앱은 보존하고, 관계없는 잘못된 즐겨찾기는 거부한다.
- `node scripts/build.mjs`: 정적 파일 14개와 JavaScript 문법 검사 통과. 서버 번들이나 별도 배포 폴더를 만들지 않는다.
- 로컬 HTTP: 허브·번호 뽑기·자리 배정·허브 모듈은 200, JavaScript MIME 정상. 제거한 앱·API·서버 파일·숨김 경로·인코딩된 상위 경로 요청은 404. HEAD는 본문 없이 200, POST는 Allow 헤더와 함께 405.
- 생성된 서버 출력·배포 메타데이터·이전 배포 파일·백엔드 의존성 폴더는 체크아웃 안의 정확한 절대 경로를 확인한 뒤 삭제했다.
- 이 실행 환경에는 `npm` 명령이 없어 package.json의 테스트·빌드 스크립트와 같은 Node 명령으로 검증했다. 아래 UI 이력은 이전 구현 시점의 확인이며 이번 전환에서 브라우저 화면을 새로 검증한 기록은 아니다. 공개 배포와 클라우드 삭제 결과는 이 로컬 검증에 포함하지 않는다.

## 이전 허브·번호 뽑기 검증 이력

2026-11-07, Node 24.22.1 / Windows / Codex 내장 브라우저.

- Node 핵심 테스트 11개 통과: 제외·기존 결과 제외·전부 추첨·후보 소진·정수 경계·회차 재등장 설정·잘못된 제외 문법·위험 URL·백업 충돌·검색·한글 URL 저장 왕복·미래 공개 앱·100앱 백업 복원.
- 허브 실제 UI: 검색 0건과 초기화, 위험 URL 저장 거부, 앱 추가→새로고침 유지→수정→즐겨찾기→JSON 다운로드→삭제→동일 파일 가져오기→다시 새로고침 유지 확인.
- 대화상자: Escape 닫기와 앱 추가 버튼으로 초점 복귀, 수정 저장 후 새 편집 버튼으로 초점 복귀 확인.
- 번호 뽑기 UI: 1~5 중 2 제외·3개 추첨 후 1/3/5 표시, 다음 3개 추첨에서 후보 부족 안내와 기존 결과 유지, 개수 1로 변경 시 남은 4만 선택. 초기화·전체 화면 진입/종료 확인.
- 반응형: 360×800 번호 뽑기, 1440×900 허브에서 가로 넘침 없음. 실제 화면 확인.
- 독립 코드 검토에서 발견한 정규화 URL 길이·최대 백업 크기·공개 앱 id 문제는 실패 테스트를 먼저 추가한 뒤 수정했고 전체 11개가 통과했다.
- 백업 크기 가정은 256KB에서 512KB로 조정했다. 허용되는 100앱의 한글 메타데이터가 256KB를 넘을 수 있기 때문이다.

검증 한계: Safari·Firefox·실제 휴대전화·스크린리더·브라우저 저장 차단 환경은 직접 검증하지 않았다. 저장 실패 처리는 코드 검토로 확인했다. 운영 배포·익명 HTTP 접속·등록 신청 결과는 실제 실행 후 별도 운영 기록에 추가한다.

## 두 번째 앱: 자리 배정

최종 범위: 사용자 수정 요청에 따른 짝꿍3분단×5행·최대30명, 고정석·빈자리 지정.

- 전체 핵심·호환 테스트23개 통과. 고정석 보존·고정번호의 무작위pool 제외·중복/제외/빈자리 충돌·좌석 부족·전원 제외·학생수 상한·입력 불변 검증.
- 독립 핵심 로직 검토에서 중요한 추가 결함 없음.
- 새 앱 즐겨찾기 저장→재방문→즐겨찾기 필터 유지 확인. 기존 v1 자료·예약 id 충돌의 로딩/백업 가져오기 회귀 테스트 포함.
- 독립 검토에서 발견한 백업 import 예약 id 충돌은 실패 테스트 후 restoreHubBackupText로 수정.
- 최종 짝꿍형 브라우저 QA: 분단3개·각10자리·총30석, 1분단1행왼쪽7번 고정, 오른쪽 지정빈자리, 학생29명 배정 확인. 재배정2회 뒤에도 고정7번과 지정빈자리 유지, 번호29개 모두 고유함을 확인.
- 고정7번을 제외 번호에 넣으면 충돌 안내와 이전29명 결과 보존·인쇄 비활성 확인. 학생27명·3번 제외로 재배정 시26명, 지정빈자리1개를 포함한 총빈자리4개 확인.
- 다른 자리에7번을 다시 고정하면 구체적인 중복 위치 안내, 대화상자 유지. Escape 닫기와 해당 좌석으로 초점 복귀 확인.
- 학생수를6으로 줄여7번 고정이 유효하지 않게 된 상태에서도 자동 배정으로 바꾸어 고정을 해제하고 정상5명(3번 제외) 배정으로 복구 확인.
- 데스크톱1440×1000에서 두 책상은 붙고 분단 사이 통로가 있는 배치 확인. 모바일360×800에서는 page scrollWidth345px, 내부 자리표 scrollWidth472px/clientWidth286px으로 페이지 가로 넘침 없음.
- 최종 UI 독립 검토에서 중요한 추가 결함 없음. 모든 JS 모듈 구문 검사 통과.
- 인쇄용 스타일과 미적용 상태 인쇄 차단은 코드로 확인한다. 내장 브라우저에서 window.print 호출은 자동화 응답을 막았고 별도 미리보기가 노출되지 않아 실제 인쇄/PDF 출력물은 검증하지 못했다.

## 역사 기록: 제거된 공용 급식·시간표

이 절은 제거 전 검증 이력을 보존한다. 현재 앱·API·서버·비밀 설정은 제공하지 않으며 아래 배포 상태가 현재 상태를 뜻하지 않는다.

- 나이스 공식 학교 조회로 세종 한솔고(I10/9300058) 확인. 인증키 없는 샘플은5행 제한이므로 운영에서는 사용하지 않는다.
- 사용자 로컬 입력 파일의 Git 제외를 확인했고, 키를 응답에 표시하지 않고 Sites secret으로 등록한 뒤 로컬 원문 파일을 삭제했다. 학생 화면에 키·로그인·설정 입력 없음.
- 실제 키로2026-11-02~08 한 주의 급식14건·시간표37건 전체 반환 확인. 실제 서버에서 같은 건수로 정규화 및6~7교시 포함 확인.
- NEIS는 JSON-only Accept 헤더에서HTTP500을 반환했고 Type=json + Accept:*/*에서200을 반환했다. 해당 차이를 실패 테스트로 재현한 뒤 수정.
- 전체 Node 테스트57개 통과. 서버22개, 학교 UI11개, Worker 빌드1개, 기존23개. 실제 실패→수정→통과를 확인했다.
- Worker 빌드에서 기존 중첩 경로·JS MIME·슬래시 이동·HEAD·금지 메서드·비공개 파일 제외·API 분리를 검사. .env나 서버 소스는 공개 자원에 포함하지 않는다.
- 독립 검토의 프론트 캐시 수명 중복 연장 문제를 수정. 원본 updatedAt와 남은 max-age를 사용해 전체5분을 넘기지 않고, 부분 오류는 캐시하지 않는다.
- 브라우저: 오늘KST 토요일의 급식 없음/주말 안내, 이전 날짜11/6의조식·중식2카드/메뉴12개, 월~금1~7교시 표시 확인. 같은 주 날짜 이동 정상.
- 모바일360×800: page scrollWidth345px, 시간표 clientWidth278px/scrollWidth590px으로 페이지 가로 넘침 없음. ArrowLeft로시간표→급식 탭 이동·초점 확인. 오늘 이동 후 금요일 메뉴가 사라지고 주말 안내가 표시됨.
- 공개 Worker는 redirect:error를 지원하지 않아 요청 전에 실패했다. 공식 런타임 문서와 실패 테스트로 원인을 확인하고 manual로 수정했다. 3xx는 따라가지 않고 오류로 처리한다.
- 2026-11-07 공개 배포 후 인증 없는 HTTP 요청에서 학교 한솔고등학교, 주간2026-11-02~08, 급식14건·시간표37건·1~7교시 정상 확인. 공개 브라우저에서 날짜 이동·평일 메뉴·전체 시간표를 확인했다.
- 공개 모바일360×800에서도 page345px, 시간표278/590px으로 페이지 넘침 없음. 학생 입력란은 날짜 하나이며 로그인·키 입력 없음.
- 허브·기존 번호뽑기·자리배정·신규 JS 경로200과 올바른 MIME, /.env.local 및 /server/index.js는404 확인. 키가 공개 코드·학생 응답에 없고 고정 학교·학급만 조회, 날짜 검증·전체 페이지·오류 정제·캐시·이전 응답 경합은 테스트와 코드 검토로 확인.
